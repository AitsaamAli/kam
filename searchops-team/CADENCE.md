# Twice-a-week cadence

Read this when the user wants to "run the team" on a regular schedule
(e.g. twice a week) rather than a one-off task. The point of a cadence is
that each session moves the project forward from where the last one left
off — running the same audit twice a week produces two audits, not growth.
`briefs/growth-tracker.md` is what makes that possible: read it first,
update it last, every session.

## Read this honestly before starting

No cadence, tool, or AI system can guarantee "maximum traffic" or
"outclass every competitor" — that depends on the competition's own
resources, how consistently the real work (publishing, fixing, building
authority) actually gets executed between sessions, and how much of it
requires a human to actually implement (writing gets drafted here, but a
developer still has to ship the code fix; content still has to get
published, not just written). Say this plainly to the user if they're
expecting guaranteed results — set the honest expectation, then build the
strongest realistic system. Real, compounding SEO growth from a
low-authority or new site typically shows meaningful traffic in 3-6
months of consistent execution, not weeks — the cadence below is built for
that reality, not a shortcut around it.

## The 8-week first cycle

Two sessions a week, 8 weeks, covers the full team once at real depth
before shifting into maintenance mode. Don't skip ahead even if it feels
slow — a technical foundation built before content is published outlasts
content built on a broken foundation.

**Week 1**
- Session 1: `onboard` workflow (full opening sweep)
- Session 2: `tech-check` workflow (fix the technical foundation before
  investing in content that would rank on top of a broken base)

**Week 2**
- Session 1: keyword-research run as a dedicated clustering pass (see the
  clustering methodology in KNOWLEDGE.md) — this is the single most
  leverage-heavy session in the whole cycle, give it real time
- Session 2: architecture — turn the clusters into a real site structure
  and internal linking plan

**Week 3**
- Session 1: `content-engine` workflow (audience → topical map → briefs)
- Session 2: brief-writer + writer-longform for the top 2-3 priority
  clusters from week 2 — start publishing, don't just keep planning

**Week 4**
- Session 1: `answer-push` workflow (snippets, PAA, voice, zero-click)
- Session 2: schema-engineer + eeat-lead — structured data and trust
  signals across what's now published

**Week 5**
- Session 1: `ai-sprint` workflow (GEO — AI visibility)
- Session 2: writer-longform / writer-technical for the next priority
  clusters — keep the publishing cadence going every week from here on

**Week 6**
- Session 1: link-strategy + outreach-prospecting (start authority
  building once there's enough published content worth linking to)
- Session 2: more content from the cluster queue + seo-editor pass over
  everything published so far

**Week 7**
- Session 1: analytics-engineer + rank-tracking (if not already set up —
  should ideally happen by week 2, but confirm it's actually live)
- Session 2: more content + digital-pr / outreach-pitching

**Week 8**
- Session 1: qa-lead — full review of everything shipped in the cycle
  against the original roadmap
- Session 2: head-search + strategy-director — review real results
  (rankings, traffic, indexed pages) against the plan and set the next
  cycle's priorities honestly, based on what's actually working

## After week 8 — maintenance/growth mode

Once the first cycle completes, sessions rotate based on what
`briefs/growth-tracker.md` shows is highest-leverage right now rather than
a fixed script:
- Content still not published from the cluster queue → keep writing
- Published content over 6 months old and decaying → refresh-pruning
- Rankings tracked and moving → double down on what's working
  (more content in that cluster, more internal links to it)
- Rankings tracked and flat → llm-visibility + intent-serp to re-diagnose
  before writing more content blindly
- New market/language being added → intl-seo + writer-localization

## Every session, in order

1. Read `briefs/growth-tracker.md` — what's already done, what's queued,
   what the last session found.
2. Read `OPERATOR-CONTEXT.md` and the current project's `briefs/current.md`.
3. Run the session's role(s) or workflow per the cycle above (or per
   maintenance-mode logic once the first cycle is done).
4. Update `briefs/growth-tracker.md` before ending the session: what got
   done, what's now queued next, and any real result observed (a ranking
   change, traffic change, an issue found) — not just "task completed."
